# Secure accounts and Elo rollout

This feature is developed on `feature/secure-accounts-elo`. It is intentionally not merged into `main`; the live GitHub Pages game is unchanged.

## Implemented in this branch

- Supabase Auth email/password registration, login, session refresh and logout.
- Auth-user profile trigger and private `abalone_get_my_player()` RPC.
- No automatic claiming of legacy passwordless profiles by username.
- Authenticated-only room creation and joining; player IDs are bound to room seats.
- Canonical starting boards and bomb positions are generated by PostgreSQL, not accepted from the browser.
- Browser sends individual move commands to the `abalone-move` Edge Function.
- Edge Function verifies the JWT, room token, seat ownership and turn, then applies the shared authoritative game engine.
- A compare-and-swap database commit prevents two concurrent moves from overwriting one another.
- Finished ranked games are settled transactionally and at most once per room; Elo uses K=32 and zero-sum rating changes.
- Room participants can see opponent username/rating; authenticated users can read their own rating history.
- Legacy browser-trusted state submission and passwordless player APIs are revoked.
- CI type-checks the engine and Edge Function, runs engine tests, checks browser JavaScript syntax, and guards against re-granting legacy passwordless APIs.

## Important rollout boundary

The code and migrations in this branch are not live. Do not merge or announce rated online play until all ordered migrations have been reviewed and applied to the intended Supabase project, the Edge Function has been deployed with its required Supabase environment, and real two-account tests have passed.

The Supabase publishable key in `index.html` is intended for browser use. The service-role key must never be placed in the frontend or committed to this repository.

## Supabase deployment sequence

1. Confirm the target Supabase project is the intended production project.
2. Review and apply migrations in filename order:
   - `202611090001_secure_accounts_elo_foundation.sql`
   - `202611090002_bind_authenticated_room_players.sql`
   - `202611090003_server_move_commit.sql`
   - `202611090004_disable_legacy_client_state_submission.sql`
   - `202611090005_room_opponent_and_rating_history.sql`
   - `202611090006_disable_legacy_passwordless_player_auth.sql`
3. Configure Supabase Auth email/password and the app's allowed redirect/site URLs.
4. Deploy `supabase/functions/abalone-move/index.ts` as the `abalone-move` Edge Function. It uses the platform-provided `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY`; the service-role secret remains server-side.
5. Run the test plan below against a non-production test environment before any production rollout.

## Required end-to-end test plan

- Register two different accounts and verify each receives exactly one profile.
- Verify duplicate usernames and duplicate emails fail without creating orphaned profiles.
- Log in, reload, refresh an expired session, and log out.
- Create a standard and mini room; verify an authenticated second account can join.
- Verify guests cannot create/join ranked rooms and the host cannot join their own room.
- Verify invalid room tokens, wrong-account tokens, out-of-turn moves, malformed moves, illegal pushes and forged client state are rejected.
- Verify simultaneous moves cannot overwrite one another.
- Finish a match and verify each player's games/wins/losses and rating history update exactly once.
- Retry the final move/settlement path and verify Elo is not applied twice.
- Abandon a match and verify no rating change occurs.
- Verify the public leaderboard exposes only intended public player statistics.

## Legacy accounts

Existing passwordless profiles are not automatically attached to new accounts by matching usernames; that would permit account takeover. Their ratings and history remain unclaimed until a separate recovery process can verify possession of the old account/device. Do not invent or manually assign ownership based only on a username.

## Rating policy

Initial rating: 270. K-factor: 32. Changes are zero-sum and ratings cannot fall below zero. A rated match is a completed, server-validated online game between two distinct registered accounts. Guests and abandoned games are unranked.
